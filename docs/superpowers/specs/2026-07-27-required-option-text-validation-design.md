# 필수 질문·셀의 옵션 상세기입 검증 설계

## 목표

필수 질문 또는 필수 셀에서 응답자가 `allowTextInput`이 설정된 옵션을 선택한 경우,
그 옵션의 상세기입 텍스트도 반드시 입력해야 다음 페이지로 진행하거나 설문을 완료할 수
있게 한다.

## 확정 규칙

- 질문의 `required`가 `true`이고 선택된 옵션의 `allowTextInput`이 `true`이면 상세기입을 필수로 검사한다.
- 테이블 셀의 `required`가 `true`이고 해당 셀에서 선택된 옵션의 `allowTextInput`이 `true`이면 상세기입을 필수로 검사한다.
- 빈 문자열과 공백 문자만 있는 값은 미입력으로 처리한다.
- 상세기입 옵션을 선택하지 않았다면 해당 텍스트를 검사하지 않는다.
- 질문이나 셀이 필수가 아니라면 상세기입 옵션을 선택해도 텍스트 입력을 강제하지 않는다.
- radio, checkbox, select와 순위형 등 현재 `allowTextInput` 옵션을 제공하는 응답 경로에 같은 규칙을 적용한다.
- 화면에 표시되지 않는 질문·행·열·셀은 기존 필수 검증과 동일하게 검사 대상에서 제외한다.

## 검증 구조

상세기입 충족 여부를 판정하는 순수 검증 함수를 설문 응답 검증 영역에 둔다. 이 함수는
질문 응답값, 선택 가능한 옵션, `optionTexts` 사이드카 값을 받아 현재 선택된
`allowTextInput` 옵션 중 텍스트가 비어 있는 항목을 찾는다.

질문 단위 검증은 기존 `required` 질문 진행 차단과 결합한다. 테이블 셀 단위 검증은 기존
`required-cells` 검증 결과에 상세기입 누락 셀을 포함한다. 동일 셀이 일반 필수 응답과
상세기입 누락을 동시에 위반해도 중복 표시하지 않는다.

테스트 모드, 공개 응답, 관리자 응답 수정은 같은 클라이언트 검증 경로를 사용하므로 동일한
동작을 적용한다. 저장 데이터 형식과 `__optTexts__` 제출 형식은 변경하지 않는다.

## 오류 표시

- 다음 또는 완료 동작을 차단한다.
- 질문 단위 누락은 기존 필수 질문 하이라이트를 사용한다.
- 셀 단위 누락은 기존 `required-cells` 배너와 셀 위치 이동 기능을 사용한다.
- 별도의 신규 오류 메시지 체계를 만들지 않고 기존 필수 응답 문구를 재사용한다.

## 테스트

- 필수 radio/select 질문에서 상세기입 옵션 선택 후 빈 값 및 공백 값은 진행을 차단한다.
- 필수 checkbox 질문에서는 선택된 상세기입 옵션마다 텍스트가 필요하다.
- 필수 선택형 셀의 상세기입 옵션이 선택됐지만 텍스트가 비어 있으면 해당 셀을 누락으로 반환한다.
- 상세기입 옵션을 선택하지 않았거나 질문·셀이 선택 사항이면 차단하지 않는다.
- 유효한 상세기입이 있으면 기존 진행·완료 동작과 제출 payload가 유지된다.
- 숨겨진 질문·셀은 상세기입 누락 검증에서 제외한다.

## 제외 범위

- 옵션별로 별도의 “상세기입 필수” 설정을 추가하지 않는다.
- DB 스키마와 응답 저장 구조를 변경하지 않는다.
- 작성 중 실시간 오류 표시는 추가하지 않고 다음·완료 시점의 기존 검증 UX를 유지한다.
